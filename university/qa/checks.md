# Реестр проверок Острова

Что вообще проверяется, чем и зачем. Реестр пополняется при каждой новой функции и
при каждом найденном баге. Проверка без владельца-сценария не считается существующей.

Запуск:

```bash
node qa/run-funnel.mjs    # воронка целиком: FUN, LVL, BEG, EDGE, ROB, FB, CNT
node qa/run-edge.mjs      # состояние, злые действия, все комбинации, злой контент
node qa/run-server.mjs    # серверные эндпоинты, в том числе без базы данных
node qa/run-admin.mjs     # админка Романа
node qa/run-resume.mjs    # раунд 2: RSM, SND, MCH, BRK, NAM
```

Точечно: `node qa/run-funnel.mjs --only=ПРЕФИКС`, `node qa/run-edge.mjs --only=STATE`.
Общая оснастка обоих браузерных наборов - `qa/harness.mjs`.

## Сценарии стенда

| Префикс | Сценарий | Что доказывает |
|---|---|---|
| `FUN` | Полная воронка, маршрут Advanced | воронка проходится от начала до карты |
| `LVL` | Basic с уровнем mid (верны №1-2, промах №3) | правило уровня внутри Basic |
| `BEG` | Basic с уровнем beginner (всё мимо) | новичок не попадает на сложные фразы |
| `EDGE` | Верен №3, промах №4 | граница маршрута: это ещё Basic, а не Advanced |
| `ROB` | Устойчивость: пустой ввод, свободный вопрос, ответ словами | игрок не по сценарию не ломает воронку |
| `FB` | Игрок не запустил кружок | воронка не встаёт намертво без звука |
| `CNT` | Контент Романа поверх дефолтов | правки из админки видны и ничего не рушат |
| `STATE` | Перезапуски и повторные входы | воронка не повторяется, прогресс не теряется, аналитика не двоится |
| `EVIL` | Злые действия игрока | двойные тапы, длинное имя, разметка во вводе, короткие реплики |
| `MTX` | Все 16 комбинаций ответов №1-4 | маршрут и уровень считаются ровно по правилу |
| `BAD` | Злой контент из админки | пустые вопросы, correct вне диапазона, битые URL, кавычки в атрибутах |
| `SRV` | Сервер, в том числе без базы | мусорные тела, чужие типы, доступы, отсутствие 500 |
| `ADM` | Админка Романа | карточки, выбор верного ответа, статистика, нумерация вопросов, поведение без данных |
| `RSM` | Перезагрузка на экране маршрута | воронка не начинается заново; показанное совпадает с записанным |
| `SND` | Отправка результата при сбое сети | результат не теряется навсегда и не двоится |
| `MCH` | Сопоставление сказанного с вариантами | «да», «нет», «5» засчитываются; двусмысленное - не выбирается молча |
| `BRK` | Битое сохранение | игрок всегда видит экран, повторный вход не кирпич |
| `NAM` | Подстановка имени в маршрут | спецсимволы имени не портят текст |

## Что проверяет каждый прогон воронки

Проверки `NN` одинаковы во всех сценариях воронки (`FUN`, `LVL`, `BEG`, `EDGE`) - меняются
только ответы на тест и ожидаемый маршрут.

**Вход и шаги**
- `01` экран разрешений показан до входа (микрофон и камера спрашиваются заранее, одним окном)
- `02` открылся онбординг-чат
- `03` кружок 1 появился в чате
- `04` после кружка 1 спрашивают имя
- `05` подсказка в поле ввода зовёт написать имя
- `06` после имени спрашивают цель
- `08` показаны 5 вариантов цели
- `09` после цели спрашивают время в день
- `10` показаны 3 варианта времени
- `11` кружок 2 появился
- `12` после кружка 2 спрашивают про опыт
- `13` показаны 3 варианта опыта
- `14` кружок 3 появился

**Тест на понимание**
- `15` тест начался с «Вопрос 1 из 6»
- `16` у вопроса есть кнопка «Послушать»
- `17` показана подсказка «это не экзамен» (обещание Романа игроку)
- `18` у вопроса ровно 3 варианта ответа

**Маршрут и данные**
- `07` имя сохранено в состоянии игры
- `19` показан итоговый маршрут
- `20` маршрут назван верно
- `21` имя подставлено вместо `{name}`
- `22` трек в состоянии верный
- `23` уровень фраз верный
- `24` цель и время сохранены
- `25` результат теста отправлен на сервер
- `26` в отправке ровно 6 ответов
- `27` в отправке тот же трек и уровень, что показаны игроку
- `28` в отправке имя, цель, время, опыт

**Выход и гигиена**
- `29` кнопка START появилась
- `30` START открывает карту острова
- `31` ноль ошибок в консоли
- `32` ноль необработанных исключений
- `33` нет горизонтальной прокрутки на 390px

## Правило маршрута, которое защищают проверки

Advanced - верны вопрос №3 И вопрос №4. Иначе Basic.
Внутри Basic: верные №1 и №2 дают фразы уровня mid, иначе beginner.
Вопросы №5 и №6 на маршрут не влияют, идут в аналитику.

Границу закрывают три сценария: `FUN` (оба верны - Advanced), `EDGE` (верен только
№3 - остаётся Basic), `LVL` (№1-2 верны, №3 мимо - Basic с mid).

## Живая проверка после деплоя

Стенд гоняет локальную сборку. Перед сдачей Роме обязательно ещё раз, на боевом:

1. Открыть `english-kombat.vercel.app/island` и пройти воронку до карты.
2. `GET /api/island/content` отдаёт контент, кружки Романа играют его видео.
3. `GET /api/island/quiz-stats` с паролем показывает прохождения.
4. Тестовые записи из аналитики удалить: `DELETE FROM island_quiz WHERE player='...'`.

## Набор раунда 2 (`qa/run-resume.mjs`)

Появился после проверки возобновления воронки, защиты от повторной отправки и нового
сопоставления реплик. Красные проверки здесь - это не поломка стенда, а открытые
дефекты продукта; список падений и есть список задач.

- `RSM-01..05` перезагрузка после показа маршрута: маршрут не теряется, воронка
  не повторяется, показанный маршрут совпадает с ушедшим на сервер
- `SND-01..04` `/api/island/quiz-result` оборван: игрок всё равно видит маршрут,
  пометка «отправлено» не ставится авансом, после восстановления сети запись доходит,
  при исправной сети запись ровно одна
- `MCH-01..06` реплики: однозначное слово выбирает вариант; «5», «нет», «да»
  засчитываются; двусмысленная реплика не выбирает первый вариант молча ни в анкете,
  ни в тесте
- `BRK-01..07` битый `S.onb` (не массив, `null` внутри, отрицательный и нечисловой
  `qi`, неизвестный шаг, строка вместо объекта): экран есть, исключений нет,
  повторный вход тоже выводит игрока
- `NAM-01..03` имена `$'`, `$&`, имя с кавычками и разметкой в тексте маршрута

## Чего пока НЕ покрывает стенд

Честный список, чтобы зелёный прогон не читался как «проверено всё»:

- реальный микрофон и запись голоса (нужно живое устройство);
- реальные видеокружки Романа (появятся, когда он загрузит их через админку);
- поведение на настоящем iPhone (там свои ловушки, см. уроки L-01, L-02);
- бой, лига, Worms-арена, живой PvP - за пределами онбординга;
- админка `admin.html` - проверяется отдельно, не этим стендом;
- распознавание речи: реплики подаются текстом через поле ввода, то есть проверяется
  сопоставление, но не то, во что ASR превращает сказанное («пять» или «5»);
- одновременная правка контента Романом и прохождение воронки игроком: клиент считает
  маршрут по контенту, загруженному на старте, сервер - по текущему в базе; расхождение
  между экраном и записью в этом случае никем не покрыто;
- реальный `localStorage`, испорченный другой версией приложения: битые сохранения
  подаются искусственно, реальных миграций между версиями стенд не проверяет.
